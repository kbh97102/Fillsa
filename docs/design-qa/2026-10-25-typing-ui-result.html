3. 검증 조건과 범위

  • 실행 환경: Android 에뮬레이터 API 35, 360×720, 160dpi, 글자 배율 1.0. 최신 Debug APK를 기존 데이터 유지 방식으로 설치.
  • 시각 상태: 라이트·다크, 키보드 열림·닫힘, 부분 입력. 기존 시각 fixture로 동일 문장을 표시.
  • 빌드·테스트: Debug 빌드 성공. TypingSaveOutcomeTest 6개, 실패 0. 공백 오류 검사 통과.
  • 범위 한계: 이번 결과는 필사 화면 수정 범위의 시각 검증입니다. 실서버 저장 성공·실패, 영문 입력, 한글 IME 조합, 긴 문장 전체 회귀를 이번 라운드에서 수행한 것은 아닙니다.
  • 정리: 조사용 임시 Kotlin 파일 제거. 기존 전체 화면 비교·수정 후보 보고서의 SHA-256이 동일함을 확인.

4. 최종 확인과 다음 단계

  1. 위 비교에서 안내 캐릭터·문구·줄바꿈·다크 배경을 확인해 주세요.
  2. 실기기에서 한글 입력과 저장 후 복귀를 확인하면 배포 전 기능 점검을 보완할 수 있습니다.
  3. 현재 변경은 로컬 미커밋 상태입니다. 검토 후 커밋·배포 준비를 이어갈 수 있습니다.

이번 변경에서 앱 버전과 서버 저장 계약은 변경하지 않았습니다.
