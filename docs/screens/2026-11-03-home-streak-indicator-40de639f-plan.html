AS-IS 데이터 흐름과 원인 분석

  1. 회원: GET /api/v2/member-quotes/weekly → MemberQuoteDay.state == "done" || completed → memberHistoryCompletedDates → HomeWeekStrip 불꽃. 일반 필사 완료값을 연속필사 표시로 사용 중인 계약 불일치가 확인됐습니다. 이것이 실제 제보 누락의 직접 원인인지는 미확정입니다.
  2. 비회원: 로컬 GetAllStreakInfoUseCase의 isDailyWritingCompleted → completedDates → 같은 날짜 줄. 회원 v2 서버 계약은 이 로컬 기록에는 적용되지 않습니다.
  3. 미선택 완료일은 보라색 원과 home_complete_badge.svg를 표시합니다. 새 댓글은 선택된 오늘의 불꽃 누락을 지목합니다. 현재 isSelected 우선 규칙은 월간 플래그가 참이어도 배지를 숨깁니다.

현재 fixture는 주간 completed만으로 10·11일을 표시하므로 월간 todayCompleted와 값이 다른 경우를 검증하지 못합니다. CLI Preview의 SVG 누락은 실제 에뮬레이터 결과와 달라 운영 증상으로 단정하지 않습니다.

해결 설계 / TO-BE

권장안: 회원 날짜별 연속필사는 월간 memberQuotes[].todayCompleted == true인 quoteDate 집합으로 판정합니다. Figma의 보라색 완료 원+불꽃 변형은 이 날짜에만 사용합니다. 주간 completed/state, 답변·좋아요, 헤더 연속 일수나 월간 합계로 날짜 불꽃을 추정하지 않습니다.

Android는 월별 todayCompleted를 같은 quoteDate의 주간 날짜에 매칭합니다. 앞뒤 날짜가 이어지는지 직접 계산하지 않습니다. 공개 Swagger는 서버의 월 경계 연속 판정 알고리즘을 정의하지 않습니다.

표시 주간이 두 월에 걸치면 두 yearMonth를 조회합니다. 기존 GetQuotesMonthlyUseCase와 응답 모델을 재사용하고 HomeViewModel에서 인증 세대별 월 캐시와 중복 요청을 관리합니다. 스크롤로 새 월이 보일 때 필요한 월만 읽으며 Home 복귀·필사 성공 후 보이는 월을 새로고침합니다. 실패 시 확인된 기존 배지를 보존하고 주간 일반 완료값으로 대체하지 않습니다. 주간 API는 명언·날짜 선택에 계속 사용합니다.

비회원 로컬 완료 경로와 Home 날짜 줄의 7칸 viewport·스크롤·선택은 유지합니다. 월간·주간 값이 다르면 불꽃은 월간 todayCompleted를 우선합니다. 새 댓글의 선택+연속필사 상태는 Figma에 변형이 없지만 사용자가 기존 배지 표시를 명시 승인했습니다. 선택 원·숫자를 유지하고 기존 home_complete_badge.svg만 같은 위치에 겹칩니다. iOS 수정은 범위 밖입니다.

수정·검증 순서

  1. 새 댓글·첨부의 선택된 오늘 누락을 Android 목데이터로 구성합니다. 실제 계정의 주간 completed/state·월간 todayCompleted는 확보되지 않아 실데이터 재현과 목데이터 검증을 분리합니다.
  2. 주간 completed=true·월간 todayCompleted=false는 배지 없음, 반대 조합은 배지 있음으로 실패 테스트를 만듭니다. 월 경계, 지연/실패 응답, 인증 전환, Home 복귀·필사 후 갱신, 비회원 로컬 완료도 검증합니다.
  3. 기존 월간 UseCase를 Home ViewModel에 연결해 월별 날짜 집합·캐시를 만들고 Home View의 회원 날짜 상태에 반영합니다. 선택 원은 유지하면서 연속필사로 판정된 선택일에도 기존 불꽃 배지를 표시합니다.
  4. :presentation:testDebugUnitTest와 :app:assembleDebug를 실행합니다. 실계정 서버 호출을 못 했다면 미검증으로 기록합니다.
  5. 구분된 완료 fixture로 Light/Dark 하위 날짜 줄 Preview와 전체 Home Preview를 렌더해 Figma와 비교합니다. Preview SVG 누락은 실제 360×821 에뮬레이터 전체 프레임으로 별도 확인합니다. 최대 5차 비교 후 차이가 남으면 최종 Pass로 표시하지 않습니다.
  6. 화면 문서·독립 QA 기록·AS-IS/TO-BE HTML을 갱신하고 보고 직전 Notion을 재조회합니다. Notion 상태는 별도 요청 없이 변경하지 않습니다.

위험·복구·판단 필요 사항

todayCompleted를 일반 completed와 혼동하면 연속필사하지 않은 날짜에 배지가 생깁니다. 월 경계는 최대 두 월 조회가 필요해 중복 요청·실패·인증 세대 보호를 설계합니다. 기존 날짜 스크롤 회귀 테스트를 다시 실행하며 이 이슈의 변경만 별도 경계로 복구합니다. 기존 사용자 작업 두 파일은 보존합니다.

선택+연속필사 UI 예외는 사용자가 승인했습니다. 제보 캡처는 확보했지만 실제 Android 계정의 월간 todayCompleted 값은 없습니다. Swagger만으로 서버의 월 경계 판정과 실계정 응답은 확정하지 않습니다.

검증: Figma 노드와 현재 소스 Preview, API31 Light/Dark 실제 런타임을 대조했습니다. 실계정 Android 응답은 확인하지 못했습니다. HTML 로컬 링크 10개는 유효하고 미치환 토큰은 없습니다. 연결 가능한 브라우저가 없어 넓은/좁은 화면의 HTML 시각 점검은 미실시했습니다.
